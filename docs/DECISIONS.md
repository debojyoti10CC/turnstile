# Decisions

| Date | Decision | Alternatives | Reason |
|---|---|---|---|
| 2026-09-11 | Channel boxes are never deleted | Delete on close + tombstone | Deleting resets totalClaimed → replay of old vouchers on re-fund. Salt gives fresh channels |
| 2026-09-11 | claim = accounting, settle = sweep | Transfer per claim | Mirrors EVM binding; one transfer for many channels |
| 2026-09-11 | Stale claim rows are no-ops | Revert | Idempotent settler retries; one bad row shouldn't sink a batch |
| 2026-09-11 | Withdraw delay in seconds (latest_timestamp), 900–2,592,000 | Rounds | Same units/bounds as EVM & SVM bindings |
| 2026-09-11 | payerAuthorizer may also start/finalize withdrawals | Payer only | Funds always go to payer, so hot key gains no theft path; lets agents exit without the cold key |
| 2026-09-11 | No voucher expiry | expiresAt field | SVM binding requires expiresAt = 0 for the same reason: withdraw delay already bounds redemption |
| 2026-09-11 | escrow-client/tests build every app-call's box/account/asset references explicitly and disable algokit_utils's simulate-based auto-population (`populate_app_call_resources`/`cover_app_call_inner_transaction_fees: False`) | Rely on `allowUnnamedResources` auto-discovery per CLAUDE.md §7 | On this algod 4001/algokit_utils 4.2.3 pairing, letting the composer auto-discover resources for an ABI *method call* (as opposed to a bare app call) intermittently routes through an internal fee-probe codepath that submits a synthetic create+delete "op-up" stub transaction and misreports a `group fee too small` error instead of the real missing-resource error. Explicit refs are deterministic and match what a production facilitator would compute anyway (CLAUDE.md already calls for simulate-based *discovery*, not blind reliance at submit time) |
| 2026-09-11 | `claim()`'s extra fee is computed as `ceil(n * 2600 / 700) * minFee` | Flat `1 * minFee` guess | Matches CLAUDE.md §1's op-up formula exactly: n=1 row needs `ceil(2600/700)=4` op-up inner transactions, each consuming one network min-fee from the pooled group credit. Verified empirically on LocalNet — 3 op-ups (3000 µAlgo) under-funds and fails with `group fee too small`; 4 (4000 µAlgo) succeeds |
| 2026-09-11 | LocalNet dev-mode timestamp-offset tests submit one throwaway 0-amount payment immediately after `algod.set_timestamp_offset()` before the time-sensitive call | Call the time-sensitive method directly after setting the offset | Empirically, algod only applies a newly-set dev-mode offset starting from the block *after* the one it was set on — the very next submitted transaction still sees the old effective timestamp. A harmless "latch" transaction (unique note, to avoid `TransactionPool.Remember: transaction already in ledger` on repeat calls) forces that extra block so the following call sees the advanced clock |
